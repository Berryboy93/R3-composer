## Critical Additions

### 1. AI Fallback Strategy
**Problem:** If AI inference times out (>10s), user is stuck  
**Solution:** Deterministic fallback compositions with clear warning

```typescript
// Fallback progression (always works)
I-V-vi-IV → generates in <100ms
Pentatonic melody arpeggio
4-on-floor drum pattern
Standard 8/8/8/4/4 arrangement structure
```

### 2. Offline-First Architecture
**Problem:** Browser refresh loses all work; no sync strategy  
**Solution:** Service Worker + IndexedDB + CRDT-based conflict resolution

- Compositions editable offline
- Queued AI requests process when online
- Automatic merge of collaborator changes
- Zero data loss guarantee

### 3. Latency Budget Breakdown
**Problem:** "P95 <10s" is meaningless without breakdown  
**Solution:** Every millisecond accounted for

```
Harmony Agent:    6000ms (timeout fallback)
Melody Agent:     5000ms (parallel)
Drum Agent:       4000ms (parallel)
Bass Agent:       4000ms (parallel)
Arrangement Agent: 8000ms (sequential)
Validation:        100ms
Network (2×):      200ms
─────────────────
Total:          ~8.5s (P95: 10s with fallback)
```

### 4. Real-Time Collaboration (CRDT)
**Problem:** Multi-user editing without conflicts = impossible  
**Solution:** Conflict-free replicated data types (Yjs/Automerge)

- Client A adds melody; Client B adds bass
- Both reconnect → both changes merge
- No manual conflict resolution needed
- Identical state on all clients guaranteed

### 5. Rate Limiting & Quotas
**Problem:** Free tier users could DDoS inference servers  
**Solution:** Quota enforcement at API layer

```
Free:   25 generations/month
Pro:    Unlimited
Studio: Shared team quota
```

### 6. Complete Zod Schemas
**Problem:** Appendix B had placeholders (`z.object({...})`)  
**Solution:** Full schemas for every data structure

- HarmonyResultSchema (chords + analysis)
- MelodyResultSchema (notes + contour)
- DrumPatternSchema (hits + groove)
- ArrangementSchema (sections + energy curve)
- CompositionSchema (full composition)
